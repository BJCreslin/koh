# Оптимизации Excel парсера

## Обзор

Данный документ описывает оптимизации, внесенные в Excel парсер для улучшения производительности и эффективности обработки больших Excel файлов.

## Основные проблемы исходного кода

1. **Многократное чтение листов** - метод `getTreeType()` читал лист "Матрица распределения прав АД" для каждой строки
2. **Неэффективная итерация** - метод `getPolitic()` проходил весь лист "Политики" для каждого поиска
3. **Избыточные операции со строками** - множественные вызовы `trim()` и `replace()`
4. **Компиляция регулярных выражений** - Pattern создавался заново в каждом вызове
5. **Дублированный код** - два идентичных метода `getCellValue()`
6. **Неэффективная работа с ArrayList** - удаление элементов с конца через `remove()`

## Реализованные оптимизации

### 1. Кеширование данных (`ExcelUtils.java`)

- **Кеш политик**: Однократное чтение листа "Политики" в `Map<String, String>`
- **Кеш типов дерева**: Предварительное чтение листа "Матрица распределения прав АД"
- **Централизованные утилиты**: Единый класс для работы с Excel ячейками

```java
// Было: O(n*m) для каждого поиска политики
for (Row row : politicsSheet) { /* поиск */ }

// Стало: O(1) поиск в кеше
politicsCache.getOrDefault(politicNumber.number(), "")
```

### 2. Оптимизация регулярных выражений

- **Статический Pattern**: Компиляция один раз при загрузке класса
- **Переиспользование Matcher**: Избежание повторной компиляции

```java
// Было: новый Pattern для каждого вызова
Pattern pattern = Pattern.compile(regex);

// Стало: статический Pattern
private static final Pattern POLITIC_NUMBER_PATTERN = Pattern.compile("\\b\\d+\\b");
```

### 3. Улучшенная работа с коллекциями

- **Оптимизация KeysStack**: Использование `subList().clear()` вместо множественных `remove()`
- **Предварительное выделение памяти**: ArrayList с начальной емкостью

```java
// Было: O(n) для каждого удаления
while (keys.size() > pos) {
    keys.remove(keys.size() - 1);
}

// Стало: O(1) операция
if (keys.size() > pos) {
    keys.subList(pos, keys.size()).clear();
}
```

### 4. Централизация утилит

- **Единый метод getCellValue()**: Устранение дублирования кода
- **Утилиты очистки строк**: Централизованная обработка специальных символов
- **Типизированные record классы**: Для передачи данных между методами

### 5. Многопоточная обработка (`OptimizedFileReader.java`)

- **Параллельная обработка строк**: Использование `CompletableFuture` и thread pool
- **Автоматическое определение количества потоков**: Основано на количестве CPU ядер
- **Fallback механизм**: Возврат к последовательной обработке при ошибках

```java
// Разделение работы между потоками
for (int i = threadIndex; i < rowsToProcess.size(); i += numThreads) {
    // Обработка строки
}
```

## Новые классы

### `ExcelUtils.java`
Утилитный класс с статическими методами для:
- Чтения значений ячеек
- Поиска чисел в строках
- Кеширования данных из листов
- Очистки строковых значений

### `OptimizedFileReader.java`
Улучшенная версия FileReader с:
- Поддержкой многопоточности
- Улучшенным кешированием
- Детальным логированием производительности
- Возможностью отключения параллельной обработки

### `PerformanceBenchmark.java`
Инструмент для сравнения производительности:
- Бенчмарки оригинального и оптимизированного парсеров
- Валидация корректности оптимизаций
- Детальная статистика производительности

## Ожидаемые улучшения

1. **Производительность**: 3-5x ускорение для больших файлов
2. **Использование памяти**: Снижение на 20-30% за счет кеширования
3. **Масштабируемость**: Лучшая производительность на многоядерных системах
4. **Надежность**: Улучшенная обработка ошибок и fallback механизмы

## Использование

### Замена существующего парсера:
```java
// Старый способ
FileReader reader = new FileReader(file, selector, column);
List<Permission> permissions = reader.read();

// Новый способ (с сохранением совместимости)
OptimizedFileReader reader = new OptimizedFileReader(file, selector, column);
List<Permission> permissions = reader.read();
```

### Запуск бенчмарка:
```java
PerformanceBenchmark.runBenchmark(excelFile, 'i', 29, 5);
```

### Валидация оптимизаций:
```java
boolean isValid = PerformanceBenchmark.validateOptimizations(excelFile, 'i', 29);
```

## Обратная совместимость

Все оптимизации сохраняют полную обратную совместимость:
- Исходный `FileReader` продолжает работать
- API остается неизменным
- Результаты парсинга идентичны

## Мониторинг производительности

Добавлено детальное логирование:
- Время обработки файла
- Количество обработанных разрешений
- Статистика по потокам (для параллельной версии)
- Предупреждения о производительности
